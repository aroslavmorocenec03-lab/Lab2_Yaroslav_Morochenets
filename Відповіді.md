# Відповіді на контрольні запитання

**Ярослав Мороченець. Лабораторні роботи 1–3.**

## Лабораторна робота 1

### 1. Як створити Git-репозиторій?

У потрібній папці виконати git init. Для копії готового сховища виконати git clone <URL>.

### 2. Як долучити файл до репозиторія для контролю версій?

Виконати git add <файл>, а потім git commit -m "Опис змін". Команда add поміщає поточну версію файлу в індекс.

### 3. У скількох станах можуть перебувати файли в Git?

Три основні стани відстежуваного вмісту: modified (змінений), staged (проіндексований), committed (збережений у коміті). Новий файл додатково може бути untracked, а файл за правилом виключення — ignored.

### 4. Яка команда визначає стан файлів?

git status показує гілку, індексовані й неіндексовані зміни та невідстежувані файли. Стислий вигляд: git status --short.

### 5. Для чого використовується .gitignore?

Щоб виключати ще не відстежувані файли з пропозицій додавання. Наприклад, *.txt ігнорує текстові файли. Для вже відстежуваного файлу правило не припиняє контроль версій автоматично.

### 6. Як переглянути непроіндексовані зміни?

git diff порівнює робоче дерево з індексом. git diff --cached показує зміни індексу відносно HEAD.

### 7. Якою командою фіксуються зміни?

git commit -m "Змістовний опис" створює коміт із проіндексованих змін. Перед ним потрібно виконати git add.

### 8. Як видалити файл із Git-репозиторія?

git rm <файл>, потім git commit. Щоб припинити відстеження й залишити файл на диску: git rm --cached <файл>, далі коміт і за потреби правило .gitignore.

### 10. Як переглянути історію комітів?

git log; для компактного графа всіх гілок — git log --oneline --graph --all --decorate.

### 11. Як змінити останній коміт?

Підготувати потрібні зміни через git add і виконати git commit --amend. Для збереження повідомлення додати --no-edit. Команда змінює хеш коміту, тому вже опубліковану спільну історію без погодження не переписують.

### 12. Яка команда створює нову гілку?

git branch <назва> лише створює гілку. git checkout -b <назва> або git switch -c <назва> створює гілку та переходить до неї.

### 13. Як об’єднати гілки А та Б?

Якщо результат має бути в А, спочатку перейти до А командою git checkout A, а потім виконати git merge B. Якщо виникли конфлікти, виправити файли, проіндексувати їх і завершити коміт злиття.

## Лабораторна робота 2

### 1. Для чого використовується add?

git add переносить поточний вміст указаних файлів до індексу для наступного коміту; також позначає вирішені конфлікти.

### 2. Для чого використовується init?

git init ініціалізує репозиторій у поточній або вказаній папці. Повторний виклик у готовому репозиторії не видаляє його історію.

### 3. Для чого використовується status?

git status показує стан робочого дерева та індексу, поточну гілку і стан її синхронізації з віддаленою гілкою, якщо вона налаштована.

### 4. Для чого використовується commit?

git commit зберігає знімок індексу в локальній історії разом з автором, часом, повідомленням і посиланнями на батьківські коміти.

### 5. Що писати в коментарях комітів?

Коротко описувати зміст і мету логічно завершеної зміни. Приклади з роботи: First Commit, addition, New feature added. Для складних змін після короткого заголовка пояснюють причину.

### 6. Для чого використовується checkout?

Для переходу між гілками або до конкретного коміту, а в режимі з указанням файлів — для відновлення їхнього вмісту. Сучасні окремі команди: switch для переходів і restore для файлів.

### 7. Для чого використовується reset?

git reset може знімати зміни з індексу або пересувати поточну гілку до коміту. --soft зберігає індекс і робочі файли; --mixed скидає індекс; --hard скидає також робочі файли та може знищити незбережені зміни.

### 8. Для чого використовується log?

Для перегляду історії комітів, їх хешів, авторів і повідомлень. Параметри --oneline та --graph дають коротке подання з графом гілок.

### 9. Як відновити кілька файлів із попереднього коміту?

Виконати git restore --source=<хеш> -- file1 file2. Потім перевірити git diff і за потреби зафіксувати зміни. Старий еквівалент: git checkout <хеш> -- file1 file2.

### 10. Як перейти до попереднього коміту по імені?

Використати його хеш або тег: git checkout <хеш> чи git switch --detach <хеш>. Для безпосереднього батьківського коміту — HEAD~1. Повернення до гілки: git checkout master.

### 11. Як перейти до попереднього коміту по коментарю?

Спочатку знайти хеш через git log --all --grep="текст повідомлення" --oneline, потім виконати git checkout <знайдений хеш>. Саме повідомлення не є унікальним ідентифікатором, тому результат пошуку потрібно перевірити.

### 12. Як створити нову гілку?

git branch new_feature. Також можна відразу створити й відкрити її: git checkout -b new_feature.

### 13. Як перейти на нову гілку?

git checkout new_feature або git switch new_feature. Перед переходом слід перевірити незбережені зміни.

### 14. Як перейти на основну гілку?

git checkout master або git switch master. Назва залежить від сховища: в інших проєктах основна гілка може називатися main; master не є обов’язковою назвою для всіх репозиторіїв.

### 15. Як виконати повне злиття гілок?

Перейти до гілки-приймача і виконати git merge <гілка-джерело>. Щоб явно створити коміт злиття навіть за можливості fast-forward, додати --no-ff. Саме так злиті гілки калькулятора.

### 16. Як виконати часткове злиття гілок?

Для перенесення окремих комітів використати git cherry-pick <хеш1> <хеш2>. Для окремих файлів — git restore --source=<гілка> -- <файли>, потім add і commit. Окремої універсальної команди partial merge в Git немає.

## Лабораторна робота 3

### 1. Для чого використовується clone?

git clone <URL> створює локальну копію репозиторію з історією, налаштовує origin і відкриває початкову гілку. За типової конфігурації також створюються посилання на віддалені гілки.

### 2. Для чого використовується remote?

Для керування підключеннями до інших репозиторіїв: remote add додає адресу, remote -v показує адреси, remote remove видаляє підключення, remote set-url змінює URL.

### 3. До чого відноситься ім’я origin?

Це звичайне локальне ім’я віддаленого репозиторію. Git clone використовує його за замовчуванням; це не спеціальна гілка і не назва облікового запису GitHub.

### 4. Для чого використовується pull?

git pull отримує зміни через fetch і інтегрує їх у поточну гілку. Залежно від параметрів і налаштувань інтеграція відбувається через merge або rebase. У роботі використано pull --ff-only, що дозволяє лише fast-forward.

### 5. Для чого використовується push?

git push надсилає локальні об’єкти й оновлює дозволені посилання гілок або тегів у віддаленому сховищі. Приклад: git push -u origin master.

### 6. Для чого використовується revert?

git revert <хеш> створює новий коміт, який скасовує зміни вибраного коміту, зберігаючи історію. У роботі так скасовано Bad feature; сам цей коміт залишається доступним у журналі.

### 7. Для чого використовується fetch?

git fetch origin завантажує нові об’єкти й оновлює віддалені посилання. Сам по собі fetch не зливає зміни з поточною гілкою і не змінює робочі файли.

### 8. Для чого використовується .gitignore?

Для правил ігнорування невідстежуваних файлів. Файл зазвичай розміщують у корені робочого дерева або в його підпапках, а не в .git. У роботі правило *.txt перевірено командою git check-ignore -v notes.txt.
